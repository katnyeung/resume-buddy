## Your Task

Generate insights that help the user understand their career profile and take action.

### 1. Skill Themes (5-6 categories)
Group O*NET tasks into intuitive skill themes using SIMPLE, DESCRIPTIVE names:
- ✅ GOOD: "Backend Development", "Cloud Architecture", "Team Leadership"
- ❌ BAD: "Core", "Technical", "Software Development" (too vague)
- ❌ BAD: O*NET jargon like "Interacting with Computers" or "Making Decisions"

For each theme, assign a coverage score (0-10):
- **9-10**: Multiple STRONG tasks, deep expertise evident
- **7-8**: Mix of STRONG + MODERATE tasks, solid capability
- **5-6**: Mostly MODERATE tasks, developing skill
- **3-4**: Mix of WEAK + MODERATE, emerging capability
- **0-2**: WEAK or NONE, gap area

### 2. Career Summary (1-2 sentences)
Describe the candidate's market position. Focus on:
- What roles they're qualified for (e.g., "senior backend engineer", "cloud architect")
- Their standout capabilities (e.g., "strong cloud architecture and testing foundations")
- Their value proposition (e.g., "can design, build, and maintain production systems at scale")

### 3. Key Strengths (3-5 bullet points)
Focus on **BOTH O*NET TASK COVERAGE PATTERNS AND SKILL EVIDENCE**, not specific achievements (those are shown elsewhere).
Describe which types of work activities the candidate demonstrates consistently, and which skills they have credible evidence for.

Format: **[Category]: [Coverage pattern from O*NET tasks AND skills]**

✅ GOOD Examples (Combined task + skill patterns):
- "Software Lifecycle Management: Strong evidence across testing, validation, modification, and performance optimization tasks (5 STRONG tasks) with demonstrated skills in JUnit, Docker, CI/CD (3 STRONG skills)"
- "System Design & Analysis: Consistently demonstrates analyzing requirements, designing systems, and predicting outcomes (4 STRONG tasks) supported by Java, Spring Boot, Microservices expertise (3 STRONG skills)"

❌ BAD Examples (specific achievements - avoid these):
- "Backend Development: Deep expertise in Java microservices" (too specific, not about O*NET task coverage)
- "Achieved 50% performance improvement" (achievement, not task coverage pattern)
- "Built API gateway on OpenShift" (project detail, not task pattern)

Focus on: How many O*NET tasks they cover AND how many skills they demonstrate with evidence, which task/skill categories, and coverage strength (STRONG/MODERATE).

### 4. Growth Opportunities (2-3 bullet points)
High-impact areas to strengthen for senior roles. Make them ACTIONABLE:
