## Your Task

### Part 1: Map Description Lines to O*NET Activities/Tasks

For EACH description line, identify:
1. Which O*NET **Activities** it demonstrates (can be multiple)
2. Which O*NET **Tasks** it demonstrates (can be multiple)
3. Confidence score for each mapping (0.0-1.0)
4. Extract any quantifiable impact metrics
5. Assess impact level and scope

### Part 2: Map Skills to O*NET Tasks

For EACH extracted skill, identify which O*NET **Tasks** require that skill:
- Example: "Java" skill → "Write, analyze, review Java programs" task
- Example: "Testing" skill → "Develop or direct software testing" task
- Example: "Kubernetes" skill → "Deploy containerized applications" task

Focus on direct skill requirements for tasks. Only map skills that are clearly needed to perform the task.

### Part 3: Recruiter Perspective Analysis

For EACH description line, provide a recruiter's evaluation:

**Strong Signals** - What makes this line appealing to recruiters:
- **Industry Expertise**: Specific industries (banking, healthcare, e-commerce, etc.) and their value
- **Scale & Responsibility**: Metrics indicating seniority (user count, request volume, team size)
- **Business Impact**: Revenue, cost savings, customer satisfaction improvements
- **Technical Depth**: Modern tech stack, architectural complexity, best practices
- **Reliability**: Uptime, performance, production stability indicators
- **Leadership**: Team leading, mentoring, project ownership signals

**Potential Questions** - What recruiters might want clarified:
- Role clarity (lead vs contributor vs owner)
- Team context (solo work vs team collaboration vs leading)
- Specific contributions vs team effort
- Technology choices and constraints
- Business outcomes beyond technical metrics

**Recruiter Appeal Score** (0-10):
- 9-10: Exceptional - Clear senior+ impact with quantifiable results
- 7-8: Strong - Good technical depth with measurable outcomes
- 5-6: Solid - Demonstrates competence but lacks specifics
- 3-4: Weak - Vague or generic, needs more detail
- 1-2: Poor - Red flags or unclear contribution

**Best Fit Roles** - Which job titles this line appeals to (be specific):
- Consider seniority level (Junior, Mid, Senior, Staff, Principal, Lead)
- Consider specialization (Backend, Frontend, DevOps, Architect, etc.)
- Consider industry fit

**Red Flags** (if any):
- Vague claims without evidence
- Buzzwords without substance
- Unclear personal contribution
- Unrealistic metrics
- Missing context

## Mapping Guidelines

**Confidence Scoring**:
- 0.90-1.00: Direct match - line explicitly describes this activity/task
- 0.70-0.89: Strong match - line clearly implies this activity/task
- 0.50-0.69: Moderate match - line partially relates to this activity/task
- <0.50: Weak match (don't include)

**Impact Metrics**: Look for numbers like:
- Performance metrics: "99.95% uptime", "10K requests/sec"
- Scale: "5 engineers", "10 million users"
- Improvements: "50% faster", "reduced costs by $100K"
- Time: "6-month project", "delivered in 2 weeks"

**Impact Level**:
- Critical: Business-critical systems, major organizational impact
- High: Significant team/department impact, important systems
- Medium: Notable individual/small team contribution
- Low: Routine work, minor improvements

**Scope**:
- Individual: Personal contribution
- Team: Affects immediate team (2-10 people)
- Department: Affects department/division (10-100 people)
- Company: Company-wide impact (100+ people)
- Industry: Industry-level innovation or standards
